# MAIM Publishing Director

Version: 0.1.0

1. Read references/publishing_canon.md. Identify collection, edition, reader role, goal, pain point and current artifact; use existing evidence before asking for missing context.
2. Inventory existing skills and collection sources before making duplicates. Build a book job with job_id, collection_id, book_id, edition, source_refs, owner, stage, dependencies, budget ceiling, outputs, checks and unresolved decisions. Default new spending ceiling to zero.
3. Route recovery to maim-book-source-archivist; voice intake to existing Major Voice/Raw Thought skills; drafting to maim-book-author; edition adaptation to maim-integrity-edition-author; review to maim-book-evidence-editor; packaging to maim-book-production-editor. Reuse existing brand/design specialists.
4. Keep stages planned → recovery → outline → interview → draft → evidence_review → layout_review → release_candidate. Use blocked with a concrete missing input. Do not call release_candidate published. Read existing owner authorization before introducing an approval gate.
5. Keep a collection-specific source and version manifest. Allow cross-links only with original source IDs, rights and edition context. Never merge four ten-item systems into one list.
6. Return a queue with verified status, next artifact, assigned role, dependencies and direct GitHub continuation links. Distinguish role definitions and saved skills from active runtime agents. Do not invent independent reviews or ongoing background execution.

Read [publishing_canon.md](references/publishing_canon.md) before work. Report missing sources and actual execution limits.
